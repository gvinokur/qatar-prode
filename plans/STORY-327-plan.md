# Story #327 Plan: Group Email Invitations and CSV Import

## Context

Story #327 implements the "Email" tab within the existing `InviteFriendsDialog` component. The tab currently shows a "Coming Soon" placeholder. The goal is to allow group admins to invite multiple users by email — either via manual name/email entry or CSV upload — with an optional custom message. The system must send localized invitation emails (EN/ES) and enforce a 50-invitation-per-batch limit.

**Mockup reference:** `docs/mockups/extended-invitations.html` (Tab 1 — Email)

---

## Acceptance Criteria
- [ ] Email tab implemented in `InviteFriendsDialog`
- [ ] Manual entry: dynamic list of Name/Email pair rows (add/remove)
- [ ] CSV import: parse uploaded file with Name and Email columns
- [ ] Template download: provide a CSV template file
- [ ] Custom message: optional text field
- [ ] Email sending: localized EN/ES emails with the group invite link
- [ ] Rate limiting: max 50 invitations per batch (server-side enforcement)
- [ ] Feedback: success/error states shown after sending

---

## Technical Approach

### New Component: `EmailInvitationsTab`
Extract the Email tab logic into a dedicated Client Component (`app/components/friend-groups/EmailInvitationsTab.tsx`) to keep `InviteFriendsDialog` manageable (currently ~330 lines; the tab logic adds ~150 more).

Props:
- `groupId: string`
- `groupName: string`
- `shortUrl: string` (already generated by dialog, pass it in)
- `locale: string`

### Server Action: `sendGroupEmailInvitations`
Added to `app/actions/prode-group-actions.ts`.
- Auth check: user must be logged in and be owner OR admin participant of the group
- Validate: ≤ 50 recipients, valid email format (Zod)
- For each recipient: generate email with the group invite link, send via `sendEmail`
- Returns: `{ sent: number, failed: string[] }`

### New Email Template: `generateGroupInvitationEmail`
Added to `app/utils/email-templates.ts`.
- Inputs: recipientEmail, recipientName, senderDisplayName, groupName, inviteLink, customMessage, locale
- Localized via `getTranslations({ locale, namespace: 'emails' })`
- Includes: group invite CTA button, invite link text, optional custom message block

### CSV Parsing
Client-side using `FileReader` API (browser native, no additional dependency).
- Accept `text/csv` and `.csv` extension
- Parse: skip header row if it matches name/email pattern, extract Name and Email columns
- Populate the manual entry rows

### CSV Template Download
Generate a simple CSV string client-side and trigger a browser download (`Blob + URL.createObjectURL`). No server round-trip needed.

### Rate Limiting
- Server action validates `recipients.length <= 50`
- Client-side: disable "Send" button and show warning chip when count > 50

## Mid-Level Design

### Call Graph Changes

**New flow — Group email invitations:**
```
EmailInvitationsTab [Client]
  └── sendGroupEmailInvitations [server action]
        ├── getLoggedInUser
        ├── findProdeGroupById
        ├── findParticipantsInGroup (admin check)
        ├── generateShortUrlForGroup + buildShortUrl (for invite link)
        ├── generateGroupInvitationEmail (util, per recipient)
        └── sendEmail (per recipient, parallel Promise.allSettled)
```

---

### `app/utils/email-templates.ts` *(modified)*

**New functions:**

- **generateGroupInvitationEmail(params)**: `Promise<{to: string, subject: string, html: string, locale: Locale}>`
  - `params: { recipientEmail: string; recipientName: string; senderDisplayName: string; groupName: string; inviteLink: string; customMessage?: string; locale?: Locale }` (locale defaults to `'es'` via `locale = 'es'` parameter default)
  - Generates localized HTML email for a group invitation with invite button, link, and optional custom message block.
  - Calls: `getTranslations` (next-intl/server)
  - Tests:
    - subject includes groupName
    - html includes inviteLink
    - html includes personalized greeting using recipient name
    - html includes customMessage block when provided
    - html omits customMessage block when undefined
    - uses provided locale for translations (defaults to 'es')

---

### `app/actions/prode-group-actions.ts` *(modified)*

**New functions:**

- **sendGroupEmailInvitations(groupId, recipients, customMessage, locale)**: `Promise<{sent: number, failed: string[]}>`
  - `groupId: string`
  - `recipients: Array<{name: string, email: string}>` — max 50 entries
  - `customMessage?: string`
  - `locale: string`
  - Validates auth (throws Unauthorized), admin status (throws Forbidden), recipient count (throws if > 50).
  - Generates invite link via `generateShortUrlForGroup` + `buildShortUrl`.
  - Sends emails in parallel via `Promise.allSettled`.
  - Returns `{ sent: number, failed: string[] }` where `failed` lists email addresses that errored.
  - Calls: `getLoggedInUser`, `findProdeGroupById`, `findParticipantsInGroup`, `generateShortUrlForGroup`, `buildShortUrl`, `generateGroupInvitationEmail`, `sendEmail`
  - **Test infrastructure:** uses `testFactories.user()` and `testFactories.prodeGroup()` for seed data; mocks `sendEmail`, `generateGroupInvitationEmail`, `getLoggedInUser` with `vi.mock`.
  - Tests:
    - throws "Unauthorized" when no session
    - throws "Forbidden" when user is neither owner nor admin participant
    - throws "Too many recipients" when recipients.length > 50
    - returns `{ sent: N, failed: [] }` for N valid recipients
    - collects failed email addresses when sendEmail throws
    - passes locale to generateGroupInvitationEmail
    - accepts exactly 50 recipients without throwing
    - deduplicates recipients by email before sending (only one email sent per unique address)

### `app/components/friend-groups/EmailInvitationsTab.tsx` *(create)*

**New component:**

- **EmailInvitationsTab(props)**: `JSX.Element`
  - `props: { groupId: string; groupName: string; shortUrl: string; onSnackbar: (message: string, severity: 'success' | 'error') => void }`
  - Client Component (`'use client'`).
  - State: `recipients: Array<{name: string, email: string}>` (starts with 1 blank row), `customMessage: string`, `isSending: boolean`.
  - Handlers: `addRow`, `removeRow`, `updateRow`, `handleCsvImport`, `handleTemplateDownload`, `handleSend`.
  - `handleCsvImport`: reads File via FileReader, parses CSV rows (skips header row if columns match name/email), populates recipients state; shows error if Email column missing.
  - `handleTemplateDownload`: creates `name,email\n` Blob and triggers browser download.
  - `handleSend`: deduplicates recipients by email, calls `sendGroupEmailInvitations`, shows snackbar via `onSnackbar` callback.
  - **Test infrastructure:** uses `renderWithTheme` from test utilities; mocks `sendGroupEmailInvitations` with `vi.mock`.
  - Tests:
    - renders one empty row on mount
    - "Agregar otro" adds a new row
    - delete button removes a row (minimum 1 row remains)
    - send button disabled when all rows are empty
    - send button disabled when recipients > 50
    - send button enabled when recipients exactly equals 50
    - shows count chip with recipient count
    - calls sendGroupEmailInvitations on send click (mock)
    - CSV parse: populates rows from valid CSV content
    - CSV parse: duplicate emails are deduplicated before populating rows
    - CSV parse: file with missing Email column shows a format error message
    - CSV parse: empty file or headers-only file results in no rows added
    - on send with partial failures (sendGroupEmailInvitations returns non-empty `failed[]`), calls onSnackbar with 'error' severity listing failed addresses
